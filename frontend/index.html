01

Search Data

Live public-platform checks, with Google dorking on standard scans when configured. We do not create search-query logs or sell search data.

Results may be cached in memory for 10 minutes. Signed-in username reports and browser search history are retained. IP-based rate limits, daily keyed IP hashes and hosting request logs support abuse prevention.

02

Account Data

Sign-in keeps your account ID, email, display name, creation time, scan allowances, plan/payment references and saved username reports.

We never sell personal data or share it for another party's marketing. Authentication, hosting and payment providers process account data. Google Analytics and advertising may process IP addresses and cookies; our analytics configuration excludes search values.

03

API Lookups

LeakCheck email lookups run over HTTPS, on the fly, without application caching or account database retention.

Other email sources receive the identifiers needed to answer a lookup. Each provider has its own privacy policy. Recent searches and investigations you save can remain in this browser.

    How this benchmark is measured+

    Scope: GitHub, GitLab and Hacker News. Five public usernames and five synthetic controls are checked every day. Reference labels require official API account objects or explicit absence. Unexpected or blocked API responses remain unscored.

    False-positive rate: FP / (FP + TN), using definitive reference negatives only. Accuracy is (TP + TN) / all definitive outcomes. Check the unknown and unscored counts before interpreting a high percentage.

    Named tools: Actual Sherlock and Maigret engines use pinned code and their own bundled detection rules. Each tool checks the same usernames and named platforms with up to three concurrent requests. Sherlock and Maigret use eight-second timeouts; MyRecon uses a six-second connect/eight-second read timeout and a 45-second sweep deadline. Endpoints, headers and validation differ; tools run in sequence on the same network. Timings exclude imports/startup and do not rank full-catalogue performance. The HTTP 200 heuristic remains an optional baseline.

    Unknowns: Native errors, disabled or unsupported sites, missing outputs and known HTTP failures remain unknown. No retries, recursive enrichment, proxies or block bypass is enabled. Raw runs record native statuses, tool versions, code revisions and detection-rule fingerprints. Older runs without a tool have gaps.

    Schedule: Daily at 03:17 UTC (08:47 IST). Scheduled jobs may be delayed. The last successful timestamp and stale-data state are shown above. No customer search data is used.

    Common questions

    What can I check with MyRecon?

    MyRecon includes public username, email and breach, password exposure, domain registration, DNS, and IP checks. Coverage and access can vary by tool, so use the live interface and current plan page to confirm what is available.

    Does a missing username result prove no account exists?

    No. A site may block, rate-limit, rename, or restrict a profile, and some services may not be supported. Treat an unavailable or missing result as inconclusive unless the source provides a verifiable reason.

    Can MyRecon confirm that a profile belongs to a person?

    No. A matching username is only a lead. Confirm important conclusions with independent public evidence and keep uncertain links unconfirmed. MyRecon does not access private accounts or restricted content.

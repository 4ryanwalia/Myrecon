We tested 35 platform-specific controls across eight platforms with the MyRecon web engine, Sherlock and Maigret on 1 November 2026. Each tool has 35 recorded outcomes, including exclusions and unresolved checks. MyRecon and Maigret each returned six source-supported matches; Sherlock returned four. No definitive false positives were observed on the scored controls. Eleven reference checks remained unresolved, and Sherlock also excluded nine controls under its current upstream policy. These limits matter when reading the results.

How the controls were selected and verified

The predeclared manifest contains 11 upstream claimed fixtures, eight upstream unclaimed fixtures and 16 generated negative candidates. They span GitHub, GitLab, Hacker News, Docker Hub, Dev.to, npm, Keybase, PyPI. Each fixture is tested only on the platform that published it as a control; this is not a cross-platform identity search. Case variants in case-insensitive namespaces are deduplicated. The 35 pairs contain 23 literal handle spellings (22 case-folded strings); repeated handles do not represent independent people.

The selection manifest records the upstream repository revision, source field, selected detection rule and rule hash for each fixture. Two deterministic 14-character alphanumeric candidates per platform are generated from the study ID, platform and index. Random-looking names are not assumed absent. Current source evidence determines their reference labels.

All reference observations were collected before tool predictions. Exact typed official API objects, explicit API absence, or a PyPI profile title naming the exact handle can establish a reference. HTML 200 alone, tool agreement, a login wall and a challenge cannot. We retain only account identifiers needed to verify the reference, response status, timestamps, response length and SHA-256, with profile contents omitted.

Stale fixtures and unresolved observations

  • Stale claimed fixture: Sherlock’s Hacker News fixture blue returned JSON null from the official API. It is a verified absence in this snapshot, despite its historical claimed label. The pg fixture was confirmed separately.
  • GitHub namespace: the official API identifies blue as an organization. This supports the tested public account namespace; it does not verify an individual person.
  • npm: all five independent reference requests returned HTTP 401. Their account truth remains unknown, including the three negative candidates.
  • PyPI: all five reference pages showed a Client Challenge. Sherlock’s negative outputs cannot be scored against those challenges. Maigret’s PyPI rule is disabled/protected and stayed unknown.
  • Keybase: the published long unclaimed fixture did not satisfy the reference’s typed absence rule. Its negative predictions are unscored; the two shorter generated candidates were verified absent.
  • Sherlock exclusions: the captured upstream exclusion list contains HackerNews and DEV Community. Their nine controls stay unknown. The study honors those exclusions even though the engine and bundled rules are pinned.

Limitations and what this study supports

This expands the earlier single-handle case to eight selected platforms and a fixed set of platform-specific fixtures and controls. It supports the dated account-existence observations and per-tool outcomes shown here. The sample favors developer/community services, contains repeated fixtures and a GitHub organization, and includes no newly created owner-controlled positive accounts. Public fixtures are upstream test inputs; we make no claim about their ownership or consent to an identity investigation. Broader consumer social networks, authenticated profiles, the Android app and whole catalogues were not measured.

The reference and MyRecon share some official API sources, so this is a publisher-run regression study rather than an independent audit. Thirty-five controls and one network window cannot estimate population error rates. Eighteen reference negatives and six positives were decisive; eleven references remained unknown. Exclusions reduce effective scope, which is why both the common planned scope and scored denominators are published. No production detection rules were changed in response to this study. Known fixtures are not a held-out evaluation, and a matching handle does not prove identity, common ownership or registration availability.

See the earlier case study and separate daily regression snapshot, the workflow comparison, and the false-positive review guide. Corrections can be reported through the contact page; replacement observations should retain their own dates.

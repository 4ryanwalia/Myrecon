The password hashes in this breach were SHA-256, which sounds reassuring and is not. SHA-256 is a general-purpose hash built for speed, the same property that makes it excellent for verifying files makes it poor for storing passwords, because consumer graphics hardware can test enormous numbers of candidates per second. Proper password storage uses a deliberately slow algorithm with a per-user salt. Anyone whose password appears in a wordlist should assume it has been recovered.

The more sensitive issue is the context rather than the fields. A gambling account is inherently disclosive: its existence says something about a person that they may not have shared, and in several jurisdictions online betting is restricted or prohibited outright. Dates of birth, phone numbers, IP addresses and country data attached to that account make the holder identifiable and locatable.

That combination is what makes this data useful for extortion rather than ordinary fraud, the threat being exposure, not theft. If a message arrives demanding payment to keep an account quiet, the data behind it has been public for a long time and payment buys nothing. Report it rather than engage. And change the password everywhere it was reused, starting with any account tied to money.

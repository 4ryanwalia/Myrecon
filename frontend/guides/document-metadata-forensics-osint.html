Local document metadata forensics with the MyRecon CLI

Documents shared online often carry author names, editing applications, company fields, revision counts, and embedded XMP timestamps that never appear on the visible page. With MyRecon, document metadata inspection runs strictly offline via the local CLI subcommand myrecon forensics, keeping sensitive evidence on your own machine with zero cloud uploads.

MyRecon editorial · Updated 2026-11-26

Key takeaways

  • Runs 100% locally via myrecon forensics <path> with zero cloud uploads
  • Requires only Python stdlib for .pdf, .docx, .xlsx, and .pptx inspection
  • Outputs SHA-256/MD5 hashes, XMP/OOXML properties, and provenance flags

CLI-only scope disclosure: zero browser uploads

Document forensics for PDF, DOCX, XLSX, and PPTX files is available only in the local MyRecon CLI (myrecon forensics <path>), not as a web upload tool on myrecon.xyz. Running locally via backend/modules/image_forensics.py guarantees requires_network=False, deterministic output, and no third-party file transmission.

OOXML provenance inspection for DOCX, XLSX and PPTX

Office Open XML files are ZIP archives containing structured metadata XML files. For inputs up to 25 MB (with a 2 MB cap per XML member), extract_ooxml_metadata() uses Python's standard zipfile and xml.etree modules to parse docProps/core.xml and docProps/app.xml without external packages.

PDF Info dictionary and XMP stream extraction

For files beginning with %PDF-, extract_pdf_metadata() inspects the PDF version header, /Encrypt protection flags, and Document Information tags (/Author, /Creator, /Producer, /CreationDate, /ModDate). It also decompresses small FlateDecode streams (up to 512 KB across 25 buffers) to extract embedded XML packets inside <x:xmpmeta>.

Deterministic hashes, provenance flags and stdlib dependencies

Every run computes SHA-256 and MD5 hashes alongside provenance flags such as author_present, multiple_authors, editing_software, company_present, and timestamp_mismatch. Document analysis uses Python's standard library alone with zero extra installs, whereas optional Pillow and numpy packages are only required when running forensics on image files for EXIF or pHash.

Chain-of-custody logging with evidence templates

Run myrecon forensics <path> --json to save structured hashes and metadata fields directly into your local case folder. Because metadata tags can be forged or stripped before publication, treat author and software strings as corroborating clues and record file hashes inside an evidence log.

Frequently asked questions

Can I upload PDF or DOCX files to myrecon.xyz for metadata forensics?

No. Document metadata forensics runs strictly offline via the myrecon forensics <path> CLI subcommand so sensitive files never leave your machine.

Do I need Pillow or numpy installed to inspect PDF and Office documents?

No. Document inspection for .pdf, .docx, .xlsx, and .pptx uses only Python standard library modules such as zipfile, zlib, hashlib, and xml.etree. Pillow and numpy are only required for image EXIF and pHash checks.

What file size limits apply in myrecon forensics?

backend/modules/image_forensics.py enforces a 25 MB maximum file size (MAX_BYTES) and a 2 MB cap per embedded XML or decompressed stream member.

Does a timestamp_mismatch or author field prove who created a file?

No. Metadata fields reflect whatever software or template last wrote the file and can be edited or left over from templates. Always corroborate metadata with file hashes and independent sources.

Discord ID to Creation Date: What a Discord ID Reveals

Published 25 November 2026 · 7 min read

Every Discord account, server, channel and message has a long numeric ID. Most people never look at one, but an ID carries a fact that names and profiles do not: the exact moment it was created. That makes it useful for spotting a brand-new account pretending to be an old friend, telling two look-alike accounts apart, and filing a precise report. This guide shows how to read the date out of any Discord ID, what an ID does not reveal, and how to use it without overreaching.

Decode a Discord ID

Paste a user, server, channel or message ID. The date is calculated in your browser from the number itself; nothing is sent to MyRecon or to Discord.

Formula from Discord's developer documentation, "Snowflakes", read 25 November 2026. Discord's own worked example, 175928847299117063, decodes to 2016-04-30 11:18:25.796 UTC.

What a Discord ID is

Discord's documentation says it uses "Twitter's snowflake format" for IDs, and that they are "guaranteed to be unique across all of Discord", with rare exceptions where a child object shares its parent's ID. An ID is a 64-bit number. Discord sends it as a string in its API because many programming languages cannot hold a number that large exactly.

The 64 bits are split into four parts:

The four parts of a Discord snowflake ID, as documented by Discord.
PartBitsWhat it holds
Timestamp63 to 22 (42 bits)Milliseconds since the Discord epoch, the first second of 2015 (1420070400000 in Unix milliseconds)
Internal worker ID21 to 17 (5 bits)Which Discord worker generated the ID
Internal process ID16 to 12 (5 bits)Which process on that worker generated it
Increment11 to 0 (12 bits)A counter that goes up for every ID generated on that process

Only the timestamp is meaningful to anyone outside Discord. The worker, process and increment values are internal bookkeeping.

How to work out the date by hand

Discord documents the calculation as (snowflake >> 22) + 1420070400000. In words: shift the ID 22 bits to the right, which leaves only the timestamp, then add the Discord epoch. The result is a Unix time in milliseconds.

  1. Take the ID, for example 175928847299117063.
  2. Shift it right by 22 bits (the same as dividing by 4,194,304 and dropping the remainder): 41944705796.
  3. Add 1420070400000: 1462015105796.
  4. Read that as Unix milliseconds: 30 April 2016, 11:18:25.796 UTC.

One trap if you do this in a spreadsheet or in JavaScript: ordinary numbers cannot store an 18 or 19 digit integer exactly, so the last digits get rounded and the date comes out slightly wrong. Use a big-integer type (BigInt in JavaScript, plain integers in Python) for the shift.

How to get someone's Discord ID

You need Developer Mode switched on in your own Discord app. Discord's support article gives the path: on desktop, User Settings → Advanced → Developer Mode; on mobile, tap your avatar, then the cog, then Advanced under App Settings. Then right-click a user (desktop) or tap the user and the menu (mobile) and choose Copy User ID. The same menus offer Copy Server ID and Copy Message Link.

What the creation date tells you

  • How old an account is. A user ID's timestamp is when the account was created. An account that claims to be a friend's "old account" or a long-running community member but decodes to last week is a warning sign.
  • Which of two look-alikes is the original. Impersonators copy names and avatars. They cannot copy an ID. If a creator's real account dates from 2017 and the one messaging you dates from yesterday, you know which is which.
  • When a server was set up. A server ID decodes to the server's creation time, useful when a "giveaway" or "official support" server turns out to be days old.
  • When a message was sent. A message ID carries its own send time, independent of what a screenshot shows.

What a Discord ID does not reveal

An ID is not a lookup key into private data. It does not contain or reveal the person's email address, phone number, IP address, location or real name. Anyone who claims they can "find someone's IP from a Discord ID" is either running a scam or describing something that requires that person to click a link they control.

It also does not prove who is operating the account: it identifies the account, not the human.

Names are a weaker identifier than they used to be for a different reason. Discord explains that usernames used to carry a four-digit tag, the discriminator, and that "we are removing tags/discriminators and introducing new, unique usernames and display names". Display names can be changed "from one minute to the next", and server nicknames override them inside a server. The ID is the one thing that stays fixed for the life of the account.

Using IDs in reports and evidence

  1. Record the ID with the name. When you save evidence of harassment or a scam, note the user ID, the username and display name at that time, and the message link. Names can change before a moderator reads your report; the ID will not.
  2. Note the creation date. If an account is days old, say so in the report. It helps reviewers see a pattern of throwaway accounts.
  3. Do not publish IDs with private context. Sharing a user ID together with private messages or personal details can expose people who are not part of the problem. Report through Discord instead of posting publicly.

Common questions

Can I see when a Discord account was created?

Yes. Copy the user ID with Developer Mode on and decode it: the first 42 bits are the creation time in milliseconds since the start of 2015. The decoder on this page does the calculation in your browser.

Can a Discord ID reveal someone's IP address or location?

No. A Discord ID holds a creation timestamp and internal Discord counters. It contains no email, phone number, IP address, location or real name.

Does a Discord ID change if the user changes their name?

No. Usernames, display names and server nicknames can change, but the user ID stays the same for the life of the account, which is why it is the best identifier to record in a report.

Why does my spreadsheet give the wrong date for a Discord ID?

Discord IDs are up to 64 bits, larger than ordinary spreadsheet and JavaScript numbers can store exactly, so the last digits get rounded. Use a big-integer type for the calculation.

OSINT Glossary: Key Terms, Verification Concepts & Spelling Notes

This A-Z reference defines the core terms used across MyRecon guides, control studies, and tool comparisons as of 26 November 2026. It also documents frequent mobile keyboard typos and brand spelling variations so researchers land on accurate documentation rather than lookalike sites.

1. Core intelligence and recon terms (O-S)

Open-source intelligence starts with precise vocabulary so investigators distinguish public collection from unauthorized access. Each term below describes lawful review of publicly reachable sources.

OPSEC (Operations Security)
Practices that limit unintentional exposure during research or personal audits, such as separating test handles and stripping file metadata before sharing.
OSINT (Open-Source Intelligence)
Structured collection, verification, and correlation of publicly available web, registry, social, and infrastructure records without bypassing access controls.
Pivot
Moving from one verified identifier, such as an email domain or PGP key, to a related public record while logging each step separately.
Reconnaissance
Early-stage public discovery mapping where handles, domains, and exposed services appear before any deeper manual review.
SOCMINT (Social Media Intelligence)
Public-source analysis focused on social profiles, bios, timestamps, and declared outbound links visible to signed-out or authorized viewers.

2. Enumeration and signal verification terms (C-U)

Handle scanners only stay reliable when they report response uncertainty honestly. These five terms explain how MyRecon separates confirmed leads from ambiguous web responses.

Control Probe
Testing a known existing account alongside a verified missing handle so detectors catch broken rules when websites change their templates.
Digital Footprint
The aggregate public trail created by handles, bios, indexed posts, domain registrations, and breach disclosures associated with an identifier.
Found / Not Found / Unknown
Three-state enumeration verdicts: found indicates profile-specific evidence, not_found matches a verified absent pattern, and unknown preserves timeouts, CAPTCHAs, or login walls.
HTTP 200 Trap
A server returning status code 200 for an invented handle because the route renders an application shell or sign-in screen instead of HTTP 404.
Soft 404
A page returning HTTP 200 while visibly stating that the requested user or page does not exist, fooling naive status-only scripts.

4. Search and spelling clarifications

Keyboard slips and missing punctuation are common on mobile browsers, and mistyped domains can expose readers to phishing lookalikes. The notes below connect frequent spelling and operator slips observed in search logs to the right official workflow.

5. Verification rules and ethical boundaries

Every term in this glossary sits inside strict ethical and evidentiary boundaries. A matching handle never proves two accounts belong to the same person, and an unavailable check never confirms that a handle or address is clean.

Use MyRecon strictly for self-audits and authorized research, never for stalking, harassment, or attempting private access. For hands-on query syntax and upcoming tooling context, visit our cheat sheet or the 2026-2027 landscape brief.

Frequently asked questions

Why do OSINT glossary entries include common search typos?

Users researching tools on mobile keyboards frequently mistype technical words like reconnaissance or OSINT. Including clear spelling notes helps readers reach verified methodology guides instead of dubious lookalike domains.

What is the difference between a soft 404 and a true unknown verdict?

A soft 404 occurs when a platform serves a missing-profile message or login shell alongside HTTP 200 status. An unknown verdict explicitly records that a block, timeout, or ambiguous template prevented verification.

How does k-anonymity protect password checks in MyRecon?

MyRecon hashes the password locally in your browser and sends only the first five hex characters of the SHA-1 digest to Pwned Passwords. The full password and complete hash never leave your device.

What does an AT Protocol DID represent on Bluesky?

A Decentralized Identifier such as did:plc or did:web permanently identifies a Bluesky account even if the owner changes their public handle or custom domain.

Why do typo-squatted sites target misspellings like osnit, myrekon, or sherlok?

Opportunistic sites often register lookalike domains or ads around frequent keyboard slips such as osnit or myrekon and sherlok to capture email addresses or push misleading installers. Always check the address bar domain before running any lookup.

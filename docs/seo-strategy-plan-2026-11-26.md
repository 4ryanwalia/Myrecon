## 1. Executive Summary & Verified Production Baseline

### 1.1 Production Architecture & Non-Production Traps

MyRecon's live search-facing property is the **pre-rendered static site inside `frontend/`**, configured in `frontend/.vercel/project.json` (`rootDirectory: "frontend"`, `buildCommand: "npm run build"`, `outputDirectory: "."`). The repository contains three critical architectural boundaries that M2 and M3 implementations must respect:

1. **Generator-Driven Build Pipeline (`frontend/scripts/build-site.js`):** Running `TZ=UTC node scripts/build-site.js` executes 17 generator/enhancer scripts (`build-breaches.js`, `build-case-files.js`, `build-data-api.js`, `build-seo-pages.js`, `build-blog.js`, `build-llms.js`, `enhance-content-pages.js`, `build-discovery-pages.js`, `build-watch-pages.js`, `build-html-sitemap.js`, `enhance-site-footer.js`, `finalize-editorial.js`, `build-visible-breadcrumbs.js`, `version-site-assets.js`, `install-google-tag.js`, `install-adsense-tag.js`) and restores hand-authored `frontend/index.html`, then executes `build-username-chart.js`, `enhance-article-promotion.js`, `install-app-nudge.js`, `enrich-story-experience.js`, `canonicalize-links.js`, `anchor-headings.js`, and `build-sitemap.js`. Editing generated HTML files directly (such as `frontend/username-checker.html`, `frontend/free-osint-tool.html`, `frontend/digital-footprint-checker.html`, `frontend/reverse-username-lookup.html`, `frontend/features.html`, `frontend/videos/*.html`, `frontend/blog/*.html`, `frontend/vs/*.html`, or `frontend/guides/*.html` built from JSON) is overwritten on the next build.
2. **Asset-Hashing Build Trap (`npm run build`):** `npm run build` runs `build-site.js && optimize-assets.js`, which rewrites stylesheet/script URLs across `frontend/` to content-addressed hashes under `/assets/optimized/*`. Never commit `optimize-assets.js` hash rewrites during editorial iterations; develop and test via `TZ=UTC node scripts/build-site.js`, serve locally via `python -m http.server 8000 --directory frontend`, and verify with `npm run test:seo` and `node scripts/seo-audit.js`.
3. **Non-Production Traps (Do Not Edit as Live Frontend):**
   - Root `web_main.py` and root `vercel.json` belong to the legacy Python backend target, not `https://www.myrecon.xyz`.
   - `docs/nextjs-seo-kit/` React components are a separate non-deployed kit. **Exception:** `docs/nextjs-seo-kit/data/content/<kind>/<slug>.json` IS the live source of truth for `frontend/scripts/build-seo-pages.js` (which syncs JSON records into `frontend/content/seo-pages/` and compiles static HTML into `frontend/`).

4. **65 Pages with `slowAnswers > 0`:** Priority commercial and informational pages (including `/whatsmyname-alternatives.html`, `/osint-tool-pricing.html`, `/username-sweep-vs-deep-search.html`, `/vs/sherlock`, `/about.html`, `/blog/best-username-search-tools.html`, and `/guides/account-enumeration-false-positives`) open one or more H2 sections with a first `<p>` exceeding 70 words, reducing snippet/AI extraction precision.

However, `/directory.html` pulls **280 impressions at pos 10.1** (mostly breach queries like `"ashley madison scandal"`) and competes with dedicated `/breaches/` and `/breaches/case-files/` pages; `frontend/index.html:45` still contains a leftover commented `msvalidate.01` placeholder (`PASTE-BING-TOKEN-HERE`) beneath the live token on line 35.

### 2.3 Parasite SEO, Site Reputation Abuse (Aug/Nov 2026 Shift) & AI Co-Citation

1. **Google Site Reputation Abuse Policy & Aug 2026 EEA Split:**
   - Google's canonical Spam Policies (`https://developers.google.com/search/docs/essentials/spam-policies`) and November 2024 clarification (`https://developers.google.com/search/blog/2024/11/site-reputation-abuse`, following `https://blog.google/products-and-platforms/products/search/google-search-update-march-2024/`) prohibit third-party content published on host domains without close first-party oversight.
   - **August 28/30, 2026 EEA Algorithmic Isolation Shift:** Effective **August 30, 2026** (`https://developers.google.com/search/blog/2026/08/update-site-reputation-policy`), following European Commission Digital Markets Act (DMA) discussions, Google stopped applying Site Reputation Abuse manual action ranking demotions inside the EEA (`https://searchengineland.com/google-wont-respect-manual-actions-for-site-reputation-abuse-in-european-economic-area-459898`, `https://searchengineland.com/google-sends-notifications-for-site-reputation-abuse-policy-manual-actions-that-dont-apply-in-the-european-economic-area-500669`) and replaced them in the EEA with **algorithmic isolation** (`https://www.searchenginejournal.com/google-updates-site-reputation-abuse-policy-removes-penalties-in-eea/587423/`), separating third-party sections so they rank strictly on standalone merit without inheriting host domain authority. On **November 4, 2026**, Google sent Search Console notifications confirming EEA immunity to manual suppression while maintaining full manual penalties outside the EEA (`https://www.seroundtable.com/google-email-site-reputation-policy-eea-42462.html`).
   - **Operational Conclusion for MyRecon:** Never buy sponsored posts, guest-post placements, or Web 2.0/Google Sites farms. On `myrecon.xyz`, maintain **100% first-party editorial authorship** (0 reputation-abuse flags). Off-site, participate only on open developer/community platforms using original work.
